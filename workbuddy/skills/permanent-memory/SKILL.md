# 永久记忆（Permanent Memory）

> 建立日期：2026-08-22 | 起因：2026-08-22 KK 更正「试点开始时间是 8/21 晚，不是 8/24」，暴露出 AI 凭会话上下文猜日期、不核对记忆台账的缺陷。本技能是根治方案。

## 何时必须执行本技能

1. **输出任何日期/时间相关内容前**（排期、周期、"XX 日开始/结束"、周年、提醒）
2. **新会话开始谈项目状态/进度时**
3. **用户更正任何事实（时间、数字、人名、参数）后**
4. **完成重大任务收尾时**（需要固化关键事实）

## 铁律一：日期输出前必须双核对

**禁止凭会话上下文推断或"记得"任何日期。** 输出日期前必须：

1. **跑 `date` 命令**拿当前真实日期时间（会话上下文里的时间可能过期）
2. **读工作区记忆**：`<工作区>/.workbuddy/memory/MEMORY.md`，查「关键操作参数」和待办队列里的时间线记录
3. 两者对照后才能输出。**冲突时以用户当轮指令为准，并当场更正记忆**

反面案例（2026-08-22）：试点实际 8/21 晚已开始，AI 却凭上一轮会话说"8/24 两人首登"——错误根因：没读 MEMORY.md，把"预计"当"事实"。

## 铁律二：区分「事实」与「预计」

- **事实**（已发生、有据可查）：用确定语气记录，格式 `**YYYY-MM-DD 已完成/已发生**：...`
- **预计**（未来计划）：必须带「预计」字样，格式 `预计 YYYY-MM-DD ...（待确认）`
- 预计变成事实后，**必须回写 MEMORY.md 删掉旧表述**，不允许"预计"字样残留冒充事实
- 用户口头更正 = 最高优先级事实，立即覆盖记忆中的旧表述，并注明「YYYY-MM-DD KK 更正」

## 铁律三：关键事实三处固化

用户更正或重大事实产生后，**同一轮内**完成三处同步，缺一不可：

| 处 | 路径 | 内容 |
|---|---|---|
| ① 工作区长期记忆 | `<工作区>/.workbuddy/memory/MEMORY.md` | 更新对应条目（Edit 原地改，不留旧错误表述） |
| ② 当日日志 | `<工作区>/.workbuddy/memory/YYYY-MM-DD.md` | 追加更正记录（append-only，写明谁更正、改了什么） |
| ③ GitHub 锁库 | sz-travel-ai `workbuddy/ops-baseline` 分支 `workbuddy/memory/` | 推送更正后的 MEMORY.md + 当日日志（用 PAT + REST API，参考 `.workbuddy/scripts/push_knowledge_base.py` 的模式） |

> ③ 是「永久」的保障：本地文件可能丢，GitHub 提交历史永远可追溯。

## 铁律四：没有记录就直说

记忆文件里查不到的日期/事实，**直说「记忆中没有这条记录，请确认」**，禁止编造或用"大概/应该"搪塞。
