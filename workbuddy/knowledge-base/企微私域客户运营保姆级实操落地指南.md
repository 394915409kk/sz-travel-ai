### 0.2 三条硬边界（全员必须知道，避免期望错位）

**边界一：机器人只能"说"，不能"听"。**
实测确认：机器人无法读取客户在群里发的消息（企业未开通会话存档权限，错误码853006，现阶段不申请）。所以：
- ❌ 客户在群里提问，机器人**不会也不能**自动回复；
- ✅ 客户消息的回复**100%靠人工**，响应速度靠「跟进哨兵」和群SOP兜住。

**边界二：机器人只能发到"已进群且有过互动"的会话。**
每个新群建好后，必须在群里先产生一条互动消息，机器人才具备发送资格。本指南阶段一有专门的解锁步骤。

**边界三：机器人权限 2026-08-28 到期。**
阶段一第一步就是续期（已另有8/27自动提醒）。不续期，三路自动化全部停摆。

### 步骤 1.2 创建外部客户群（Day 1-2）

**建群原则**：先集中兵力建 1 个主群跑通闭环，验证后再分线路裂变（不要一上来建一堆死群）。

| 项 | 内容 |
|---|---|
| 群定位 | 「职旅·出境游福利群」——面向全部线路的泛客户主群，内容以塞班（基本盘）为主+其他线路轮播 |
| 群名规范 | 职旅·XXX福利群（对外统一品牌前缀，方便客户识别） |
| 群主 | 指定1名主责客服（建议贝宝玉或资深销售），群主=第一责任人 |
| 建群路径 | 手机端企微 → 消息页右上角「+」→ 发起群聊 → 选择「客户」（注意：必须把微信侧客户拉进群才算客户群）→ 群名改为规范名 |
| 群配置 | 群建立后：右上角「…」→ 群管理 → ①开启「仅群主及管理员可修改群名」②人数上限设 200（前期便于管理，满员后再开500）③保存群二维码备用 |
| 责任分工 | KK 发话指定群主人选并确认建群；群主执行建群 |
| 验收标准 | ①群内有至少 5 名种子客户（从微信老客户中邀请）②群二维码已生成 ③群配置三项完成 |

### 步骤 1.3 把机器人拉进客户群（Day 2-3，两条路径都试）

**主路径：智能机器人进群（优先，可复用现有全部自动化链路）**

| 项 | 内容 |
|---|---|
| 操作内容 | 手机端企微 → 进入客户群 → 右上角「…」→ 群管理 → 添加群机器人（或「群成员」添加）→ 选择「陈桂芹的机器人」→ 确认添加 |
| 解锁互动 | 机器人进群后，群主在群里 @机器人 发一条消息（如"@机器人 你好"），完成互动解锁 |
| 获取群ID | 解锁后，在电脑终端执行：`wecom-cli message aibot sessions list`，在返回的会话列表中找到新群名称，记下 chat_id，**登记到客户跟进表所在知识库文档或运营手册**（后续推送都用它） |
| 责任分工 | 群主执行拉群+互动；WorkBuddy AI 或 KK 在电脑端执行 sessions list 拿群ID |
| 验收标准 | `sessions list` 中出现该客户群且能取到 chat_id |

**备用路径：群机器人 Webhook（若智能机器人无法加入客户群）**

| 项 | 内容 |
|---|---|
| 操作内容 | 群内右上角「…」→ 群机器人 → 添加机器人 → 新建 → 命名「职旅小助手」→ 复制 Webhook 地址（形如 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxxx`） |
| 使用方式 | 用任意工具向该地址 POST JSON 即可推消息：`curl 'webhook地址' -H 'Content-Type: application/json' -d '{"msgtype":"text","text":{"content":"测试"}}'` |
| 局限说明 | Webhook 只能推送，不能与现有三路自动化的读表链路直接联动；若走此路径，需 WorkBuddy AI 另行适配（当天可完成） |
| 责任分工 | 群主建 Webhook 机器人；WorkBuddy AI 适配推送脚本 |
| 验收标准 | curl 测试消息成功出现在客户群 |

### 步骤 1.4 连通性验收（Day 3）

| 项 | 内容 |
|---|---|
| 操作内容 | 用主路径 chat_id 发送验收消息（由 KK 确认内容后执行）：`wecom-cli message aibot send --json '{"chat_id":"<客户群chat_id>","msg_type":"markdown","markdown":{"content":"【测试】职旅AI助手已就位，本条为系统验收消息"}}'` |
| 责任分工 | KK 终审消息内容；WorkBuddy AI 执行发送 |
| 验收标准 | 返回 `success: true` 且客户群内真实可见消息 |

> ⚠️ **硬规矩**：外部客户群只发 KK 审核过的成品内容。任何新话术、新活动推送，先在内部群试发+KK 确认，再进客户群。

### 步骤 2.5 群SOP（Day 7 定稿）

**群主每日5动作（约20分钟）**：

1. **早8:30** 重发群规（一分钟）
2. **9:00/14:00/20:00** 按内容日历发3条内容（10分钟）
3. **随时** 客户群内提问 → **1小时内响应**（这是群规承诺，哨兵在盯）
4. **下班前** 当日新增客户/咨询录入客户跟进表（每条30秒，见阶段五填写时机矩阵）
5. **每周五17:00后** 查看话术周固化周报，把当周好用的自创话术补录进话术库（标"客服沉淀"）

**验收标准**：连续7天每日5动作执行率100%（以客户跟进表录入记录+群消息记录为证）。

### 4.2 建议新增的第 4 路自动化（先审后装，未批不建）

「客户群早安种草推送」：每日 09:00 从内容素材池/知识库生成 1 条种草文案 → **推送前经 KK 审核队列**（或先内部群试发）→ 自动推客户群。**此项涉及对外推送，按规矩等 KK 发话后才建。**

### 4.3 自动化/人工分界三原则

1. **对外触达（发到客户群/客户私聊）= 人工执行或 KK 审核后自动**——AI 永不直接对客户说话；
2. **对内工具（提醒/话术/统计/待办）= 尽量全自动**——AI 在内部群出弹药、当监工；
3. **数据录入 = 人工 30 秒/条**——这是整个引擎唯一需要人持续投入的动作，也是飞轮的燃料。

## 第五部分：数据流转与系统打通

### 5.1 客户数据在一张表中的流转（字段填写时机矩阵）

**客户跟进表 9 字段，什么时候填什么**：

| 字段 | 填写时机 | 谁填 | 更新频率 |
|---|---|---|---|
| 客户姓名/称呼 | 首次咨询建档时 | 顾问 | 一次 |
| 来源渠道 | 建档时（对照扫码渠道） | 顾问 | 一次 |
| 意向线路 | 首次表达意向时 | 顾问 | 变化时更新 |
| 意向等级 | 每次跟进后重估 H/W/C | 顾问 | 每次跟进 |
| 最近咨询时间 | 客户主动来问时 | 顾问 | 每次咨询 |
| 最近跟进时间 | 顾问主动触达后 | 顾问 | 每次跟进 |
| 跟进状态 | 状态机流转（见下） | 顾问 | 每次变化 |
| 下次跟进日期 | 约定下次触达时间 | 顾问 | 每次跟进 |
| 顾问 | 建档时 | 顾问 | 一次（换人时更新） |

**状态机（唯一合法流转路径）**：

```
新咨询 → 已报价 → 已逼单 → 已成交（终态✅）
   ↘ 任意未成交状态 → 已沉睡（>7天未跟进，AI自动判定口径）→ 激活话术触达 → 回到 已报价/已逼单
```

> 注意：「已沉睡」不是人工标的，是 AI 沉睡激活器按">7天未跟进"口径筛出来的运营概念；表中状态列由顾问维护，AI 扫表时按时间口径兜底判断，两者不冲突。

### 5.2 客户标签自动更新机制（当前能力与边界）

| 层面 | 现状 | 说明 |
|---|---|---|
| 企微原生渠道标签 | ✅ 自动 | 渠道活码扫码自动打，零人工 |
| 企微客户标签（分层） | 👤 手动 | 顾问在客户资料页打"H热/W温/C冷"标签，与表格同步维护；企微未开放标签 API 给当前机器人 |
| 跟进表意向等级 | 👤 手动30秒 | 顾问下拉选择，这是 AI 三路自动化筛选的数据源，**必须及时更新** |
| 未来升级路径 | 📌 记录在案 | 若后续开通会话存档或企微标签 API 权限，可实现"成交自动打标+分层自动同步"，现阶段不申请不纠结 |

### 5.3 三条打通链路（引擎如何与群运营咬合）

**链路一：客户群 → 表（获客数据入库）**
客户扫码/入群/群内提问 → 顾问 30 秒录入客户跟进表 → 客户进入 AI 监控视野。

**链路二：表 → AI → 内部群（弹药+监工）**
三路自动化每日扫表 → 激活话术/超时提醒/周报推「职旅日报群」→ 顾问按提醒执行动作。

**链路三：内部群 → 客户群/客户（人工触达闭环）**
顾问从推送中复制话术 → 粘贴发送到客户群或客户私聊 → 客户回应后回到链路一更新表格。

**一句话**：数据从客户来（人工录入），弹药从 AI 出（自动生成），扳机由顾问扣（人工发送），周报让 KK 看见飞轮转速（自动统计）。
